# ty 0.0.20 adapter API notes

Facts needed when touching `async_doctor_ty` against the pinned ty/ruff
`=0.0.20` crates. Prefer reading this before guessing API locations.

## Symptom

Adapter bumps fail to compile, or typed receivers stop resolving, after a ty
pin change or a copy-paste from newer Astral docs.

## Cause

ty/`ruff_*` crates are internal components with no semver promise; symbol homes
move. This repo pins `=0.0.20` and isolates all calls in `async_doctor_ty`.

## Fix or workaround

Verified against **0.0.20** (2026-10-30):

- `ProgramSettings` lives in `ty_python_core::program` and carries
  `python_environment`.
- Call `SearchPaths::try_register_static_roots` after
  `SearchPathSettings::to_search_paths(..., &FallibleStrategy)`.
- Parse via `ruff_db::parsed::parsed_module` on `ProgramFile`.
- Enable return-type inference (`ReturnTypeInference::Always`) so typed
  receivers resolve more often.
- Lambda bodies stay deferred unless the lambda is invoked; offload-passed
  lambdas are cut.
- The scan path argument may be a project directory or a single `.py` file.

Bump ty/ruff only in a dedicated PR with benchmarks (see
[`../decisions/2026-10-30-clean-room-mit.md`](../decisions/2026-10-30-clean-room-mit.md)).

## Guardrail

Workspace `Cargo.toml` exact pins; architecture invariant that only
`async_doctor_ty` depends on ty/ruff (`ARCHITECTURE.md`). None yet that
auto-checks these symbol paths after a bump — update this note in the same PR.
